# Modularization roadmap — work toward v0.16.0

**Status:** in progress, unreleased. **Base release:** v0.15.28. This document describes implementation boundaries and migration gates; it does not describe a completed modular architecture.

## Motivation and invariants

`src/App.tsx` still owns layout assembly and cross-tool commands, but SVG drawing, export helpers, audio preferences/event scheduling and notation rendering now have separate owners; settings validation and export mapping are delegated to `settingsController.ts`, while diagram appearance/overlay/annotation state is now feature-owned. The aim is for it eventually to assemble the application shell. Migrate incrementally: no changes to chord results, ranked realizations, default controls, SVG/PNG/ZIP and notation export content, sound (including sample mapping), localization, or accepted older JSON settings files.

The analytical Stradella register model is **instrument configuration**, not sound configuration. Its `bass` and `chord` ranges are modeled starting octaves and C–B/F–E groupings, not physical reed measurements. Playback-specific settings (`soundSource`, sample registers, volume, `laMelodiosaFollowStradellaRegisters`) remain separate in `src/audio/useSoundSettings.ts`. A future adapter may consume the instrument's *nominal* model when sampled playback follows that model; never merge these state domains.

## Phase 1: instrument, language and settings file I/O (implemented)

| Module | Owns | Intentionally does not own |
| --- | --- | --- |
| `src/instrument/useInstrumentState.ts` | Side, Stradella bass count, treble layout/rows/size, piano range, octave labels, four nominal register fields, and their derived `stradellaRegisterModel` | Sound source, La Melodiosa sample registers, playback settings, chord-finder request/realization state |
| `src/settings/useLanguageSettings.ts` | Language preference, browser-language observation, `accordionTools.interfaceLanguage.v1` persistence, document `lang`, and translation callback | Musical terminology or catalog definitions |
| `src/settings/settingsSchema.ts` | Exact existing partial JSON settings type, including historical aliases | Runtime validation or migrations |
| `src/settings/settingsPersistence.ts` | Fetching editable defaults with `cache: no-store`, JSON parsing, and JSON download (original filename/indentation) | Applying setters or modifying import precedence |
| `src/App.tsx` (temporary compatibility adapter) | Connects stable feature state setters to the settings controller; supplies the current settings snapshot; tool state, rendering, exports, and playback orchestration | Field validators, import precedence rules, JSON projection, settings file I/O |

The initial extraction deliberately retains individual React state setters and the original `default-settings.json` / settings-export key order.

## Phase 2: settings controller (implemented in this patch)

`src/settings/settingsController.ts` now implements three separate typed entry points:

- `applyStartupSettings(defaults, setters)` validates **editable startup defaults**. It respects the persisted `accordionTools.interfaceLanguage.v1` value, including `auto`; if browser storage throws, a valid default language is accepted as before.
- `applyImportedSettings(settings, setters)` applies only supplied valid fields to the running session. An explicitly imported language goes through `changeLanguage()` and remains persisted. Legacy `chordLabelMode` (`roman`, `tonal-function`) and `bassPatternBarsPerChord` fallback behavior stay unchanged.
- `collectCurrentSettings(snapshot)` defines the **118 keys and their insertion order** in exported JSON, including historical aliases. `App.tsx` supplies the current values without deciding the JSON format.

`SettingsSetters` is a typed adapter to the current feature-state owners, held in a stable `useRef` in `App.tsx`. It does not move audio or instrument state into settings; the controller only validates and routes values. Keep setter identity stable when extracting future feature hooks. The initial startup effect still runs once and fetches editable defaults with `cache: no-store`. The parsing/downloading implementation remains in `settingsPersistence.ts`.

`npm run test:modules` now executes **golden action-trace comparisons** recorded from the original Phase 1 implementation for seven settings scenarios, plus exact export-key ordering. It checks import versus startup precedence, legacy fields, invalid values, clamping, and register/sample separation. The fixtures are regression evidence, not a new settings migration specification.


## Phase 3a: Scale Finder and Treble Chord Finder (implemented in this patch)

- `src/features/scaleFinder/useScaleFinder.ts` owns Scale Finder request/presentation state (active, root, pattern, treble row limit, path display) and computes highlights for treble or Stradella via the **existing** selection algorithms. The Stradella result continues to be computed when highlighting is hidden, matching the previous contract.
- `src/features/trebleChordFinder/useTrebleChordFinder.ts` owns Treble Chord Finder request/presentation state (active, root, chord family, inversion, octave, voicing mode, voicing-note visibility) and delegates button selection to the unchanged treble chord engine.
- `App.tsx` retains **temporary** tool exclusivity, manual-change resets, UI panel composition, shared diagram composition, playback commands, and settings adapters. Hooks return the same stable setter functions and original physical `DiagramButton` objects; import/export format, musical result ordering, and translations are not modified. Do not transfer one Finder's selection state into the other; cross-tool commands are a later stage.
- `scripts/finder-feature-modules.test.mjs` exercises the actual hook modules using React hook stubs and musical engine spies: exact defaults, inactive/active cases, branch routing, setter exposure, and physical button identity. It is included in `npm run test:modules`. Existing chord/Stradella regression scripts continue to validate musical computation independently.

## Phase 3b: Stradella Chord Finder (implemented in this patch)

- `src/features/stradellaChordFinder/useStradellaChordFinder.ts` owns the request and presentation state: active flag, root/chord family/mode, requested slash bass, max buttons/span/minimum nominal note gap, optional root-bass marker, selected realization, explanatory note levels and font/visibility, and pending progression selection key. It exposes the **same setter callbacks** used by settings imports and existing UI commands.
- `useStradellaChordFinderResults()` receives the physical `DiagramButton[]`, current manual, and `stradellaRegisterModel` from the **instrument** hook. It delegates search to the unchanged `stradellaChordFinderTools.ts` engines. Preserve their argument order, ranked candidates, original `playbackButtons` identities, non-playable fallback, selected-index clamping, and input-dependent reset effect. For progression handoff, compare sorted `playbackButtons` IDs: bass vs counterbass and optional visual root guides must never be conflated.
- `App.tsx` still owns mutual tool activation, shared diagram rendering, playback orchestration, and batch-export timing (`flushSync`). The Stradella result and its ID sets are now supplied by the feature selector instead of duplicated App memos/effects. Sound/sample preferences and physical instrument register fields remain outside the feature.
- `scripts/stradella-finder-module.test.mjs` exercises hook defaults, engine delegation, inactive fallbacks, result clamping, exact candidate IDs, reset sequencing, and physical progression handoff using a TypeScript transpilation/test stub; the musical ranking and registration suites remain the independent computation checks. Included in `test:modules`.

## Phase 3c: ABC Player (implemented in this patch)

- `src/features/abcPlayer/useAbcPlayer.ts` now owns the ABC editor and file/example catalog, score tempo, transport progress/status, active button IDs, Stradella bass/chord versus treble-symbol modes, rendered-notation visibility and reference, and all original individual setters. Catalog fetching and example text loading retain original `cache: no-store`, path construction, manifest-entry validation, error strings, and state-reset behavior. The settings controller still receives the same stable setters and its 118-key serialization is unchanged.
- `useAbcPlayerResults()` receives current physical buttons and the instrument manual/treble-like flag. It calls unchanged `parseAbc`, voice-routing and `mapAbcEventsTo*Buttons` functions to preserve separate treble/Stradella two-voice mappings, beat timing, exact button identities, missing notes and tempo-from-score synchronization while stopped/paused. `abcjs` remains eager in `src/tools/abcPlayerTools.ts` and `App.tsx` for notation: deferring it is a later shared import-boundary migration.
- `App.tsx` intentionally retains shared playback scheduling, timeout refs and cancellation, cross-tool deactivation, sound synthesis/sample playback, toolbar toggles, notation DOM rendering, and download operations. Tool UI remains inline. **State extraction is not audio-orchestration extraction.**
- Added `scripts/abc-feature-module.test.mjs` with mock engine/React-hook fixtures for state defaults, callback interface, example manifest validation and loading, original mapping and tempo contracts, and unchanged playback ownership. Registered with `test:modules`; the real musical parser is separately tested in `test:abc`.

## Combined Phase 3d: Bass Pattern Player and Sequence/Recording (implemented in this patch)

- `src/features/bassPatternPlayer/useBassPatternPlayer.ts`: owns built-in pattern and chord-progression library loading, custom patterns persisted under the existing `accordionTools.customBassPatterns.v2` key, pattern editor messages/validation/save/remove, preferences, playback UI state, and exact original individual setters for settings import. The results hook resolves selected pattern/progression, calls unchanged Stradella accompaniment engines with **identical argument order and `DiagramButton` objects**, computes total beats/missing items and active button ID sets. No sound source or nominal register model is absorbed by this module.
- `src/features/sequences/useSequenceState.ts`: owns recorded button ID/step order, path-style and numbering preferences, notation visibility and DOM ref. `appendRecordedButton` and `clearSequence` preserve original append-order numbering and reset. The results selector maps IDs to **current** diagram buttons through the unchanged `getSequenceStepsWithButtons` engine. Instrument layout changes still reset recordings through App.
- App continues to own shared timers and cancellation, audio commands, text/ABC/LilyPond/MIDI downloads, notation rendering/visibility exclusivity and physical layout; the shared services migration must handle those interdependent behaviors separately. Keep the 118-field settings contract and localization intact.
- New `scripts/pattern-sequence-feature-modules.test.mjs` verifies original defaults, bundled data loading/legend, editor save/remove and localStorage key, invalid JSON, playback-event identity, Stradella gating, sequence order and physical-button identity. It is included in `npm run test:modules`; the musical/export engines remain covered independently by existing tests.

## Combined Phase 3e: Harmony Explorer and Progression Assistant (implemented in this patch)

- `src/features/harmonyExplorer/useHarmonyExplorer.ts` owns all original independent Harmony view/selection state, settings setters and selection reset. Its result selector delegates sector construction, ring counts and localized explanation to existing music/explanation functions. `harmonyShowNoteRing`, all-family diatonic behavior, visual ring settings and defaults remain unchanged.
- `src/features/progressionAssistant/useProgressionAssistant.ts` owns the edited/recorded progression arrays, monotonic IDs, progress/notation UI state and refs, optimizer preferences, preview and active sounding-button highlighting. `useHarmonyProgressionResults()` uses a Stradella manual even when Harmony/treble is visible, invokes unchanged `optimizeStradellaProgression(..., { allowApproximations, handMovementWeight, maxRealizationsPerChord: 5 })`, and preserves original `playbackButtons` identity and active/preview precedence.
- Cross-tool commands, Harmony recording and playback callbacks, navigation, timeout scheduling, saved settings collection, ABC notation and exports remain in `App.tsx` pending shared-service refactoring. Do not change progression-to-Finder matching by sorted physical playback IDs or merge nominal Stradella registers with sound source/sample settings.
- Added `scripts/harmony-progression-feature-modules.test.mjs` to `test:modules`. The existing `harmony-note-ring-ui.test.ts` follows the moved state/results ownership while retaining behavioral assertions and UI checks. Existing Harmony musical tests remain independent of the feature hooks.

## Combined Phase 3f: diagram appearance, overlays, and Annotate Diagram (implemented in this patch)

- `src/diagram/useDiagramAppearanceState.ts` now owns original diagram geometry, label visibility, title/label typography and appearance settings. State defaults and individual setter identities remain unchanged for startup/import validation and the 118-key export projection. The shared interface-density preference remains in App; instrument construction and Stradella nominal register configuration remain in `useInstrumentState`, not in visual appearance state.
- `src/instrument/sizePresets.ts` contains the **unchanged** treble/piano button-size preset tables previously declared in App. Both App's layout-change commands and the appearance hook import the same values; this is a source move, not a new sizing policy.
- `src/diagram/useDiagramOverlays.ts` owns physical-button selection overlays and fingering controls (including label editing, clearing and deselection). Buttons are indexed by their **original physical IDs**, not by a chord, pitch class, or playback note. App continues to handle click routing, sequence append and sound playback; the hook only updates diagram marks.
- `src/features/annotateDiagram/useDiagramAnnotations.ts` owns annotation notes, editing draft, anchor/style controls, focus ref/effect, free-position and button-attached note creation, deletion, and list labels. Anchor offsets use the **unchanged SVG coordinates** and original button width/height clipping formula. Notes are still created via the existing `makeTextNote` function, with the same IDs, anchor, formatting and text trimming.
- During Phase 3f, App retained `svgPointFromMouse()`, the complete SVG JSX, SVG/PNG/ZIP serialization and shared audio; these boundaries were then extracted or narrowed in Phase 4 below. Existing layout-change/reset effects still clear text and button marks while preserving unrelated settings; no sound or export implementation was moved.
- Added `scripts/diagram-annotation-modules.test.mjs` to `test:modules`, covering old appearance defaults, state-setter identity, physical button overlay/fingering actions, annotation anchors and clipping, edit/commit/cancel/delete, and exact `makeTextNote` arguments. Existing PNG/layout regressions still cover integration source paths; **browser SVG rendering, PNG export and pointer focus require local smoke tests**. No version bump or settings schema/translation changes.

## Combined Phase 4: diagram rendering, SVG/ZIP exports, audio and notation (implemented)

- `src/diagram/components/DiagramSvgSurface.tsx` renders the SVG wrapper using the original className, viewBox, aspect ratio and DOM ref. `DiagramButtonLayer`, `DiagramConnections` and `DiagramAnnotationsLayer` render the unchanged button paths, arrows, fingering and annotation editor; the SVG's content order and class names remain stable. No new canvas transformation or changed physical IDs are introduced. App still computes per-button musical labels and contextual footer text.
- `src/diagram/diagramExport.ts` handles legacy filename rules, format dispatch, deterministic SVG/PNG ZIP entry order and SVG mouse-coordinate conversion. Synchronous `flushSync` capture followed by restoration of the original realization **remains in App**; only subsequently serialized snapshots are encoded asynchronously. Raw SVG CSS/rasterization stays in `src/download.ts` and `src/svgRasterExport.ts`.
- `src/audio/useSoundSettings.ts` now owns the original sample/synth/audio states and creates unchanged `SoundOptions`. Nominal Stradella instrument register values remain in `src/instrument/useInstrumentState.ts`, passed read-only to the sound adapter. `playbackTransport.ts` centralizes per-feature timer cancellation and the monotonic ABC pause clock. `playbackScheduling.ts` preserves the original ABC/Bass Pattern event order, beat offsets, highlight-clearing intervals, sample gains, cancellation generation, and loop completion timing. App continues orchestrating cross-tool starts/stops, Harmony progression audio, and general playback commands.
- `src/notation/notationService.ts` handles the five notation panels' common `renderAbc` options/DOM errors and extracted notation SVG downloads. `abcjs` **still loads eagerly**; the future lazy-loading phase must preserve first-use rendering and multiple notation consumers.
- Tests: `scripts/render-audio-services.test.mjs` added to `test:modules` and the earlier ABC/diagram source-location checks were retargeted. All original settings export keys/order, audio mapping engines, source algorithms, and translations remain unchanged. Full browser/manual acceptance remains a separate requirement.

## Phase 5: application shell, toolbar, typed tool registry and navigation (implemented)

- `src/app/toolRegistry.ts` is a typed inventory of all eleven existing tool sections. Its destination metadata identifies the Harmony workspace and the Stradella-specific command targets; it imports **no tool implementation, audio engine or UI panels**. It is not yet a lazy-component/plugin manifest.
- `src/app/useWorkspaceNavigation.ts` owns workspace, tool-section activation, left-panel/focus state, and expanded settings section. The hook retains the original accordion-section toggle semantics (only Progression Assistant forces Stradella), the settings-close-on-side/workspace effect and the hidden-panel restoration rule. `navigateToTool()` is the explicit **navigation portion** of Harmony/Progression/Stradella cross-tool commands; musical payload construction, realization matching, state resets and playback cancellation remain in `App.tsx` in their original order.
- `src/app/components/AppShell.tsx` owns the outer app DOM (`main`, locale, density and two-column grid), while `WorkspaceToolbar.tsx` owns the toolbar and reset-menu pointer/Escape listeners. `App.tsx` still supplies workspace/sidebar children, translation callbacks and toolbar action handlers; it has **not** become a layout-only component. The markup, CSS selectors, accessibility titles, modal state and stop/reset behavior are unchanged.
- `scripts/app-navigation-modules.test.mjs` exercises the registry and state transitions through a small React dispatcher mock, plus integration-source assertions for playback-stop ordering, toolbar controls and shell markup. The test is included in `test:modules` and can run without native esbuild. These checks supplement but do not replace browser smoke tests.
- Public version, settings JSON (118 keys), localization catalogs, musical algorithms, SVG/PNG/ZIP/MIDI/LilyPond exports, nominal instrument registers, and sound sample mappings are untouched.

## Combined Phase 6: typed views and cross-tool commands (implemented, unreleased)

- `src/App.tsx` now **only assembles the layout** using `LanguageProvider`, `AppShell`, a conditional sidebar containing `SettingsView`/`ToolsView`, and `WorkspaceView`. The previous large JSX trees were moved with their existing controls, identifiers, DOM classes, event handlers and localization keys intact to `src/app/views/`.
- `src/app/useAppController.ts` remains a **large transitional hook** that preserves all React hooks, settings setters, derived geometry/results, transport and reset actions in their original invocation order. It returns three inferred, typed view-specific prop groups (`settings`, `tools`, `workspace`) rather than exporting mutable globals or a universal store. This is an architectural intermediate point: future work should further divide its derived state and command adapters; do not call this controller a final modular solution.
- `src/app/crossToolCommands.ts` owns a small **pure command-order boundary**, not musical payloads. The cross-tool adapters explicitly preserve navigation → assignment / preview handling → Finder enable/disable → audio cancellation. Recorded/selected chord transfers clear preview and stop ABC plus Bass Pattern; progression preview preserves the chosen index and historical Bass Pattern behavior. Harmony-selected chords reset the Finder index; optimized progression steps retain the previously set sorted `playbackButtons` ID signature and do not reset realization. Stradella→Harmony still respects existing outer-family selection semantics and stop ordering.
- `scripts/app-view-and-commands.test.mjs` tests the layout/view boundaries and five deterministic side-effect traces. Legacy tests that read `App.tsx` now include the new sources, without removing their existing assertions. Future tests should prefer **observed behavior** and per-owner state transitions over concatenated source inspection; the latter is a migration bridge, not the desired final testing design.
- **No behavioral changes intended** to registered tools, instrument versus sound configuration, chord results, settings export schema (118 keys), `default-settings.json`, `accordionTools.customBassPatterns.v2`, notation, XML/SVG/PNG/ZIP/MIDI/LilyPond exports, six languages, or generated file names. Eager `abcjs` and heavy tool panels still load at startup.
- Local validation here: TypeScript and ESLint passed; all 11 module groups passed; 33 TypeScript regressions passed through a platform-neutral loader and 20 direct JS/CJS scripts passed. Full `npm run test:all`, Vite build and browser smoke tests **require Windows validation** (the inherited `node_modules` lacks compatible native binaries).

## Phase 7: controller helpers and deferred modules (implemented, unreleased)

- `src/app/controllerOptions.ts` owns display-choice constants and localized progression-option labels; `src/notation/useNotationSettings.ts` owns the existing notation presentation preferences, maintaining all setter names, default values, and the 118-key settings export schema. These extractions do **not** redesign the remaining transitional controller.
- `ToolsView` defers the Treble Chord Finder, Stradella Chord Finder, Harmony Explorer, and Progression Assistant **panels** with `React.lazy` and `Suspense`. `WorkspaceView` defers `HarmonicCircle`. The tools' **state hooks remain mounted** in the application controller, preventing loss of selections when panels are shown, hidden or still loading. The loading placeholders are transient and noninteractive.
- `src/features/abcPlayer/abcEngineLoader.ts` dynamically imports the **unchanged synchronous** `abcPlayerTools.ts` module only after the ABC editor contains nonblank text. The result hook is asynchronous only on first loading; once loaded, parsing, voice selection and button mapping remain synchronous, ordered, and use the original algorithms. A cached promise deduplicates requests; failures are visible and may be retried. The empty ABC result matches the original abcjs parser result (tempo 180, no events), independently verified before extraction. **First-use parsing can now have a short loading interval; do not claim identical first-use latency.**
- `src/notation/notationService.ts` loads `abcjs` on demand when any of the five notation panels first renders, not only when the ABC Player opens. It keeps the previous rendering options, exception text and exported SVG filename logic. A per-target request generation prevents slow imports from painting an older score over new notation; detached targets are also ignored. The ABC parser and notation service share the same deferred `abcjs` dependency under the bundler.
- `scripts/lazy-loading-boundaries.test.mjs` scans the static source-import graph starting at `main.tsx` and verifies the intended dynamic boundaries. `scripts/abc-feature-module.test.mjs` and `scripts/render-audio-services.test.mjs` now check deferred import, original first-use parsing/mapping contracts and stale-render cancellation. These tests prove source boundaries, **not actual compiled chunk sizes or browser load timing**.
- TypeScript, ESLint and all 12 module tests passed in the preparation environment. Selected musical regressions also passed. Production Vite chunks, the full `test:all` suite and browser-level first-use playback/notation must be checked on Windows because the supplied dependencies lack a Linux Rolldown native binding.

## Phase 8: transport/reset, live export capture, presentation selectors (implemented, unreleased)

- `src/audio/playbackLifecycle.ts` contains React-independent **stop/pause** orchestration for ABC and Bass Pattern playback. State setters and timer refs are passed in through typed ports, retaining the original call order, beat calculation, bass-loop cancellation generation and sound-stop calls. Existing start/schedule logic, audio engine and interval timing remain unchanged in the controller and audio services.
- `src/app/resetCommands.ts` owns exact Stradella Finder default values and the diagram-work reset ordering. It does not clear instrument-register, audio preference, or global settings. The controller still chooses when to reset each domain.
- `src/diagram/stradellaBatchCapture.ts` synchronously captures each playable realization, retaining exact index ordering, generated ASCII names, SVG serialization (including the PNG-safe path) and viewBox dimensions. The controller supplies React `flushSync` to select candidate indices; a `finally` restores the original selection before asynchronous ZIP encoding begins. Capture failure restoration is tested explicitly. Batch export remains gated by current workspace and active Finder.
- `src/app/workspacePresentation.ts` owns pure active-tool status-label precedence and responsive sidebar grid strings. No translation/catalog changes or alterations to active-tool state.
- `scripts/controller-lifecycle.test.mjs` is added to `test:modules`; source-location assertions for live capture were migrated to the new owner. TypeScript, ESLint and all 13 module-test groups passed in preparation, plus targeted Stradella/notation/i18n/audio regressions. This does not establish equivalence of browser timing, native Vite chunks, or the full Stradella configuration matrix.
- The controller is still substantial (~2,407 lines), and contains start/playback coordination, derived diagram geometry and remaining download orchestration. **This is not the end of controller decomposition or v0.16.0 release acceptance.**


## Phase 9: Start transport and diagram geometry (implemented, unreleased)

- `src/audio/playbackStart.ts` owns the exact, synchronous ABC and Bass Pattern **start** sequence. Empty event collections are no-ops; ABC clears old ABC timers, stops Bass Pattern and audio, clears progression highlighting and Finders, records its clock/beat, then invokes the existing schedule. Bass increments the loop run ID before clearing timers, stopping ABC and audio, clearing highlights/Finders and invoking the existing scheduler with that ID. The caller still provides all React setters, refs and schedule callbacks; no state store or audio engine is moved.
- `src/diagram/diagramGeometry.ts` computes SVG width/height, contextual-title text fit, note and chart footer dimensions, and annotation placement. The formulas come from Phase 8 without mathematical changes, but receive explicit typed inputs rather than closing over controller state. The controller still computes the view-model's musical content, visibility flags and chord annotations.
- `scripts/phase9-playback-geometry.test.mjs` executes transport call-order contracts and **five checked-in numerical fixtures derived from the original Phase 8 geometry** (compact treble, piano, full and compact Stradella, and empty large treble). It is included in `test:modules`. The contextual-title test now checks the new integration boundary rather than searching for its old formula inside App.
- This is not a final v0.16.0 acceptance: the controller remains the coordinator of recorded Harmony playback, per-tool sound actions and export launch. The full Windows test suite, production Vite chunk inspection and first-use browser checks must be completed before release.

## Remaining stages — not yet implemented

1. **Further controller consolidation:** Phases 8–9 now own reset, start/stop/pause transport, synchronous batch capture and pure SVG sizing. Review only the remaining shared coordination (recorded Harmony playback, export launch, any strongly coupled diagram view-model) where a smaller interface demonstrably improves maintainability; avoid cosmetic extraction. Preserve cross-tool handoff sequencing and physical playback-button IDs.
2. **Build and first-use acceptance:** Verify actual Vite code splitting in `dist/assets` or browser Network; open every deferred panel and notation view; import multi-voice ABC and test plays, pauses, resets and downloads after initial module load. Compare snapshot exports and old settings round-trips before merging. Source import-graph tests are not a substitute for this step.
3. **Release acceptance:** Full Windows test/build, browser SVG/PNG/ZIP/ABC/MIDI/notation/audio checks, locale settings compatibility; only then consider v0.16.0.
